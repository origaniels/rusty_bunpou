# Tests

    ./test-all.sh               # pipeline + Rust + headless UI (about 1 minute)
    ./test-all.sh --e2e         # + the emulator tests (AVD "bunpo" running; about 25 minutes)
    ./test-all.sh --e2e-full    # + the button crawler on the emulator (about 15 more minutes)

## What is tested where

| Suite | Where | What it checks |
|---|---|---|
| `pipeline/tests` (pytest) | host | grammar matchers (and look-alikes they must reject), readings, furigana, accepted answers, answer parts, alternative answers fitting their context |
| `rust/core` (cargo test) | host | kana input, FSRS and scheduling, SRS simulations over months, sessions (typo fixes, free retries, resume), "almost" hints on every real answer, furigana line layout of every sentence, stats, storage, import/export |
| `rust/app/tests/ui.rs` | host, headless | the real Slint UI driven through its accessibility tree: every flow (lessons, quizzes, reviews, resume, settings, backup, reports, stats, hints, dictionary chips, haptics, the Japanese keyboard's composition), and the **layout audit** on every screen and state at 411 and 360 px wide, in English and French |
| `rust/e2e/run.sh` | emulator | a learner's first two weeks, in English and French: settings, a lesson, its quiz, then five reminder cycles with the emulator clock moved forward (notification shown, opened, dismissed; intervals 4h → 8h → 1d → 3d → FSRS) |
| `rust/e2e/tour.sh` | emulator | every screen and state (dialogs, keyboard open, wrong and right answers, long pages scrolled through), audited **on the device** with its real fonts, in English and French |
| `rust/e2e/flows.sh` | emulator | reviews left halfway while Android kills the app (answers kept, resume where it stopped); the Japanese keyboard (composed kana shown in the blank and checked once, with or without confirming first) |
| `rust/e2e/crawl.sh` | emulator | **every button and switch of every screen and state, tapped for real**, each from the same saved progress: the app survives, stays in front (unless the button opens another app on purpose: file picker, dictionary), something visibly changes, and the screen it leads to passes the layout audit |

The two crawlers complement each other: the headless one (`every_control_on_every_screen_does_something_*` in
`rust/app/tests/ui.rs`, run by `./test-all.sh`) compares the app's state before and after each press,
so it catches buttons that do nothing; the emulator one uses real touches on the device, where the
keyboard opening or closing also changes the screen, so it mainly checks that every button can be
hit, the app survives and the layout holds.

## The layout audit

`rust/app/src/audit.rs` looks at what is on screen as laid out right now (headless with the test
fonts, or on the device with the real ones) and reports:

- a label (button, text, field) sticking out of the window, or out of the screen's top or bottom
  for dialogs;
- a one-line text that doesn't fit the room it was given (cut off or running into its neighbours):
  those texts are `FitText`, which flags itself "clipped" in its accessible description;
- a button or switch smaller than 32 px, or overlapping another one;
- two texts overlapping;
- the answer field or its button hidden by the on-screen keyboard.

Content scrolled under a fixed bar (top bar, menu bar, button rows) or behind an open dialog is
ignored, since it is hidden there.

## Driving the app on the emulator

Taps never use fixed coordinates: the scripts ask the app where a label is and tap there, scrolling to
it if needed (`rust/e2e/lib.sh`). The app answers such test commands only when its external files
folder holds an `e2e.on` marker, which adb can create and other apps can't (`start_e2e_hook` in
`rust/app/src/lib.rs`).

Progress files for the tests are generated by `rust/e2e/make_progress.py` (reviews due now, points
learned today, a leech, a sentence report) and pushed into the app as root.

### Emulator setup

- AVD `bunpo` (Pixel 7 profile, Google APIs image, so `adb root` works for the clock and files).
- For the Japanese keyboard test, add Gboard's Japanese QWERTY layout once: Settings > System >
  Keyboard > On-screen keyboard > Gboard > Languages > Add keyboard > 日本語 > QWERTY. The tests pick
  the layout they need (`keyboard en|ja` in `lib.sh`); without it that test is skipped.
